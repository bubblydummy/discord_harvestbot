1. 개발 환경
- OS: Windows
- Runtime: Node.js
- Language: JavaScript
- Library: discord.js
- Database: SQLite
- Package Manager: npm
- Editor: Visual Studio Code

2.프로젝트 소개
디스코드 서버에서 명령어를 통해 작물을 심고, 수확하고, 판매하며 재화를 모으는 농사 게임 봇입니다.
사용자는 밭을 관리하고 작물을 성장시켜 골드를 얻을 수 있으며, 게임 진행 상황은 데이터베이스에 저장되어 서버를 다시 실행해도 유지됩니다.

3.개발동기
평소 농장 경영류 게임을 좋아해서, 직접 간단한 농사 게임 시스템을 구현해보고 싶었습니다.
처음에는 가볍게 재미로 시작했지만, 게임 로직과 유저 데이터 저장 흐름을 직접 다뤄볼 수 있는 프로젝트라고 생각했습니다.
웹 UI까지 구현하면 범위가 커질 수 있어, 디스코드 봇을 인터페이스로 사용해 UI 구현 부담을 줄이고 내부 로직 구현에 집중했습니다.

4. 주요기능

- 작물 심기, 성장, 수확, 판매가 가능한 농사 시스템
- 유저별 골드 및 인벤토리 저장
- 상점 시스템
- 추가 골드 획득을 위한 가위바위보 미니게임
- SQLite 기반 데이터 저장

5. 게임시스템
### 작물 시스템

사용자는 인벤토리에 보유한 씨앗을 밭에 심을 수 있습니다. 작물은 정해진 성장 시간이 지난 뒤 수확할 수 있으며, 수확한 작물은 판매해 골드를 얻을 수 있습니다.

### 경제 시스템

작물마다 구매 가격, 판매 가격, 성장 시간, 연작 여부등이 다르게 설정되어 있습니다. 사용자는 어떤 작물을 심을지 선택하면서 효율적으로 골드를 모을 수 있습니다.

### 데이터 저장

유저의 골드, 보유 작물, 밭 상태 등의 정보는 SQLite 데이터베이스에 저장됩니다. 

6.명령어 목록
농장or 내농장 - 농장 패널로 이동합니다.
가위바위보 - 가위바위보 패널로 이동합니다.

7. 프로젝트 구조
discord_bot/
├── index.js
├── db.js
├── farm.js
├── farmData.js
├── farmQuest.js
├── farmstats.js
├── rps.js
├── spoke_rps.js
├── game.db
├── rps.db
├── config.json
├── package.json
├── package-lock.json
├── .gitignore
└── old_index.js


`index.js`는 프로젝트의 진입점입니다. 디스코드에서 사용자가 메시지를 보내거나 버튼을 클릭하면 `index.js`가 이벤트를 받고, 내용에 따라 `rps.js` 또는 `farm.js`로 처리를 넘깁니다.

농사 시스템은 `farm.js`를 중심으로 동작합니다. `farm.js`는 `farmData.js`에서 작물과 상점 데이터를 가져오고, `farmQuest.js`를 통해 주간 퀘스트를 처리하며, `farmstats.js`를 통해 작물별 통계를 기록합니다.

공통 유저 정보와 코인 데이터는 `db.js`에서 관리합니다.

`farm.js`, `rps.js`, `farmQuest.js`, `farmstats.js`는 모두 `db.js`를 통해 `game.db`에 데이터를 저장하거나 조회합니다.

가위바위보 시스템은 현재 `rps.js`에서 처리하며, 사용자가 버튼으로 선택한 가위/바위/보 값을 바탕으로 봇의 랜덤 선택과 비교해 승패를 판정하고 보상을 지급합니다.

8. 구현하면 서 배운점
- 디스코드 봇은 메시지 입력과 버튼 클릭 같은 이벤트를 중심으로 동작한다는 점을 이해했습니다.
- `async/await`을 사용해 메시지 전송, 버튼 응답, 예외 처리 같은 비동기 흐름을 다루는 방법을 익혔습니다.
- 유저 코인, 농장 상태, 인벤토리, 퀘스트 진행도처럼 게임 상태를 DB에 저장하고 갱신하는 구조를 경험했습니다.
- 기능이 늘어날수록 DB 처리, 농사 로직, 게임 데이터, 퀘스트, 미니게임을 파일별로 분리하는 것이 유지보수에 유리하다는 점을 배웠습니다.
- AI 도구를 활용해 코드를 작성하면서, 생성된 코드를 읽고 구조를 이해한 뒤 필요한 기능을 수정하고 확장하는 방식의 개발을 경험했습니다.
